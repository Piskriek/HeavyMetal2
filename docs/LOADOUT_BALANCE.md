# Section 2 Loadout Model

## Scope

These presets are analytically budgeted starting values, not a claim of measured competitive parity. Section 3 now supplies the distinct tracks and airborne pickups. The complete 12-combination matrix still needs playtesting across them before Section 4 tuning is finalized.

## Common Ratings

Every combination begins at 6 in Launch, Handling, Boost, and Stability. Rider and capsule offsets each sum to zero. Therefore every combined build totals exactly 24 points; there are no locked upgrades or strictly larger rating vectors.

## Actual Physics Mapping

The values shown in setup and the values applied to racers are calculated by the same `loadoutStats()` function in `src/game/loadouts.ts`.

- Full-tension launch speed: `160 + (Launch - 6) * 4` km/h.
- Maximum horizontal velocity: `2100 + (Launch - 6) * 35` simulation units/s.
- Lane response multiplier: `1 + (Handling - 6) * 0.08`. Steering damping uses its square root and lateral speed is capped consistently.
- Hop control multiplier: `1 + (Handling - 6) * 0.025`.
- Race mass: `120 + (Stability - 6) * 14` kg. Existing mass-sensitive drag, rolling resistance, restitution, and bump impulses use this value.
- Boost multiplier: `1 + (Boost - 6) * 0.065`, combined with the existing mass-sensitive impulse for active boosts and track pads.
- Bump control-loss duration multiplier: `1 - (Stability - 6) * 0.045`.

Stability is not a pure benefit: more mass retains momentum and resists bumps but decreases vertical and boost impulses. Low mass offers agility at the cost of easy displacement and increased drag. Launch is not an unbounded engine-speed upgrade: track and player input still determine the run.

## Competitive Rules

- Quick Race uses one selected existing course with a fixed preset.
- Tournament uses Rustbucket Ridge, Boomtown Run, and Woolly Wasteland in that order. The player and three opponent loadouts remain fixed throughout the cup.
- All four rider archetypes are available immediately. CPUs use the three other riders, with predefined capsule pairings generated by the same stat function.
- Rookie/Racer/Veteran changes decision intervals, look-ahead, lane-change frequency, and boost-use timing. It does not grant additional speed, charges, mass, or hidden catch-up.
- The existing slingshot power/angle controls remain skill inputs, not changes to the selected loadout.
- Custom physics is an explicit Quick Race practice checkbox. It re-enables live player speed/weight sliders and records the run as `practice`. Tournament never enables it.
- Restarting an unfinished round resets that round, not already committed cup points. A completed round cannot be scored twice.

## Cup Scoring

Finishing places award 9, 6, 3, and 1 point. A non-finisher receives zero. After the player crosses the line, rivals continue under normal physics for at most 10 seconds; remaining non-finishers are listed as DNF. There is no fabricated finish time.

Cup ties resolve by total wins, then final-round placement, then deterministic racer ID if still tied. The last fallback has no meaningful competitive preference; a later polish pass may represent it as a shared placing instead.

`commitRound()` accepts only the current session ID, round index, and course, and ignores duplicate round entries. The UI derives cup standings from committed records rather than incrementing totals in render effects.

## Section 4 Experiments

Run each of the 12 builds with matched inputs/AI seeds over every track and collect median finish time, DNF rate, bump displacement, hop-clearance success, and boost value. Test both expert play and rookie recovery. Tune against behavior and win rates, not the point-budget totals alone.
