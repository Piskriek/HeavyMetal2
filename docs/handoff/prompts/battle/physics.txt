BEHAVIOUR
- addBody(entity, spec): kind 'static' registers a collider (box, heightfield, mesh) at spec.position / spec.rotation (quaternion; default identity; rotation only needs to be supported for box and mesh, heightfield is axis aligned), with friction, restitution, tier. For a 'dynamic' spec (sphere collider only) it adds the components 'transform' (x,y,z = position, rotation if given), 'velocity' and 'body' (mass, radius from the collider, friction, restitution, damping, tier from the spec) to the entity (replace if present). 'kinematic' = a static collider that you may later move by changing... NOT needed: treat kinematic like static. removeBody(entity): removes a static collider, or the 'body' and 'velocity' components of a dynamic one.
- Heightfield: cols x rows samples, `cell` metres apart; x from position[0] to position[0]+(cols-1)*cell, z from position[2]; height = position[1] + heights[row*cols+col]; each cell is two triangles with a fixed diagonal. Mesh: positions flat xyz, indices triples; build a uniform-grid broadphase when added. Triangles collide from BOTH sides (a ball is pushed out to whichever side its centre is on). Box: oriented box.
- Dynamics per step(dt): bodies are the world entities that have transform+velocity+body, in ascending entity id order. Semi-implicit Euler: v += (gravity + force/mass) * dt; damping: v *= 1/(1+linearDamping*dt) (same for angular); then x += v * dt; rotation q integrated from the angular velocity (q += 0.5*dt*(w,0)*q then normalise). Forces from applyForce are accumulated and cleared at the end of the step. applyImpulse changes velocity immediately: v += impulse/mass.
- Substeps against tunnelling: n = clamp(ceil(speed*dt / (0.5*radius)), 1, 16) where speed is the current speed; each substep integrates, then collides. (Derive n from state only, so it is deterministic.)
- Collision of a sphere with a static collider: find the closest point on the shape to the centre (triangle: Ericson's closest-point-on-triangle; box: clamp in local space; heightfield: only the cells overlapping the sphere's bounding box, two triangles each). If distance < radius: normal = (centre - closest)/distance (if the centre is on the surface use the triangle/face normal); push the sphere out along it; velocity: remove the inward normal component with restitution (apply restitution only when the impact speed along the normal > 1.0 m/s, otherwise 0, to avoid jitter), and Coulomb friction at the contact point with proper rolling coupling: contact point relative velocity vt = v_tangent + w x (-n*radius); friction impulse = clamp so |j_t| <= mu * j_n (use inverse inertia 5/(2*m*r^2) for the solid sphere), applied to BOTH the linear and the angular velocity (this makes the ball roll without slipping on a slope). Combined restitution = max(body, collider); combined friction = sqrt(body*collider). Process up to 8 contacts per sphere per substep, re-evaluating after each push.
- Tiers: a 'racing' body collides with 'racing' statics and 'racing' bodies; a 'decor' body (debris) collides with 'racing' and 'decor' statics; 'trigger'-tier statics never push anything: they report onTrigger(entity, trigger, true) the first substep a dynamic body's centre is inside the (box) trigger, and (entity, trigger, false) when it leaves. The engine keeps the inside-set per trigger (the only extra state; a body unknown to the set counts as outside, so a body already inside on the first step reports an enter). Only box triggers are supported.
- Sphere vs sphere between dynamic bodies of compatible tiers: positional separation split by inverse mass plus an impulse with the combined restitution and friction. Process pairs in ascending (a,b) id order. A simple O(n^2) is fine up to 64 bodies; use a sorted sweep on x if n > 64.
- raycast(origin, direction, maxDistance): nearest hit over all non-trigger static colliders (box slab, triangle Moeller-Trumbore, heightfield via its triangles along the ray's cells or just per-cell marching); returns { entity, distance, point, normal } (normal facing the ray origin) or null. direction need not be normalised (normalise it, zero length => null).
- Determinism rules: iterate in ascending entity-id order everywhere (statics too); never rely on Map/Set iteration order unless insertion order is itself deterministic and documented; no floating point trig. Add a comment block at the top of physics.ts stating these rules.
- Robustness: if a body has NaN/Infinity, throw an Error naming the entity and field. Zero mass => treat as 1.

import type { ComponentDef, EntityId, Value } from '@hm/contracts';
import type { PhysWorld } from '../src/physics';

export type TestWorld = PhysWorld & { spawn(): EntityId };

export function fakeWorld(): TestWorld {
  const defs = new Map<string, ComponentDef>();
  const ents = new Map<EntityId, Map<string, Record<string, Value>>>();
  let next = 1;
  const need = (c: string): ComponentDef => { const d = defs.get(c); if (!d) throw new Error(`unknown component ${c}`); return d; };
  return {
    defineComponent(def: ComponentDef) { defs.set(def.name, def); },
    components: () => [...defs.values()],
    alive: (id: EntityId) => ents.has(id),
    has: (id: EntityId, c: string) => ents.get(id)?.has(c) ?? false,
    get: (id: EntityId, c: string) => ents.get(id)?.get(c),
    set(id: EntityId, c: string, v: Readonly<Record<string, Value>>) {
      const m = ents.get(id); const cur = m?.get(c);
      if (!m || !cur) throw new Error(`no ${c} on ${id}`);
      m.set(c, { ...cur, ...v });
    },
    add(id: EntityId, c: string, v?: Readonly<Record<string, Value>>) {
      const m = ents.get(id); if (!m) throw new Error(`entity ${id} is not alive`);
      m.set(c, { ...need(c).defaults, ...(v ?? {}) });
    },
    query: (...cs: string[]) => [...ents.keys()].filter((id) => cs.every((c) => ents.get(id)?.has(c))).sort((a, b) => a - b),
    spawn() { const id = next++; ents.set(id, new Map()); return id; },
  };
}
